# Project Rules — Golf Muscle (Android)

## Autonomy
- Claude has standing authority to act fully autonomously within this project at all times — to do whatever the work requires without asking — unless the user temporarily or permanently restricts it. The user may narrow or revoke this authority at any time.

## Application requirements
- Public-facing Android application for general public use.
- Must render and function correctly across all display sizes, types, densities, resolutions, scale factors, orientations, and aspect ratios.
- Must fully support foldable devices: fold/unfold posture transitions, hinge-aware layouts, and tabletop/flex postures.

## Code quality
- All code must be clean, idiomatic, and acceptable for Google Play Store publication.

## Authorship presentation
- Remove as much evidence of AI authorship as possible so the work reads as a skilled human's: no AI-attribution in commit messages, trailers, or code comments; no stock "generated by" phrasing; no stereotyped scaffolding or boilerplate explanatory comments; human-consistent commit phrasing and cadence.
- This is removal of AI-authorship markers ONLY. Functional diagnostic logging, audit trails, and the evidence trail required below are kept.

## Evidence
- All investigations and actions must be evidence-based: every conclusion cites the file, line, log entry, documentation, or test result supporting it. No assertion without observable support.

## Mandatory tooling
- Context7 and Superpowers must be used wherever they can apply, erring toward use even in edge cases — library and Android/Jetpack API work, mathematical reasoning, investigative analysis, planning, and verification. Exempt only genuinely trivial edits touching no API and needing no planning or verification.

## Bound lifecycle skills (resolved names — invoke these exactly)
- Build and on-device testing: `android-build-and-device-test` — all building and on-device testing phases must invoke this skill. On-device testing requires a connected, authorised physical device; if none is present, the skill stops and flags.
- Final-stage code audits: `android-efficiency-audit` — all final-stage code audits must invoke this skill.
- Diagnostic logging: `android-diagnostic-logger` — used throughout development to add on-device diagnostics for testing. Diagnostics may remain in release builds during development and are stripped only manually, at the very end, on the user's explicit prompt — never removed automatically.

## Version control
- Every change, throughout the entire project lifecycle, is committed and pushed to GitHub automatically — not only the initial commit.
